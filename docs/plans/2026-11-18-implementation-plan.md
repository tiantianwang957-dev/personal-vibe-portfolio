# 个人 Vibe Coding 作品集实施计划

## 目标

交付一个可在 GitHub Pages 运行的中文静态作品集第一版，优先完成排版、内容结构、轻量切换和项目详情；照片与缺失截图先用占位视觉，后续可直接替换。

## 实施顺序

1. 建立 Vite + TypeScript 静态项目与质量脚本。
2. 建立统一内容数据，避免首页与详情页重复维护文案。
3. 完成明亮实验室风的首页、项目/运营切换与基础翻页。
4. 完成四个项目和三类运营经历的静态详情页。
5. 完成响应式、键盘焦点、减少动态效果和媒体失败降级。
6. 运行格式、类型、测试和生产构建。
7. 扫描敏感信息，初始化 Git 并提交；创建远程前复核公开范围。

## 第一版素材策略

- 海信与 AIGC 使用抽象封面占位，暂不复制原素材。
- 使用率平台只展示虚构数据的脱敏示意，不读取或打包生产数据。
- 口袋公园、微博、自媒体与个人照片均使用明确占位卡。
- 简历按钮保留，但 PDF 在公开信息复核前不进入仓库。

## 验收

- 首页可以切换项目与运营内容，按钮、键盘和移动端均可用。
- 所有案例入口可进入详情页。
- 无内部人名、门店、账号、Token、Cookie、生产备份或联系方式。
- `format:check`、`typecheck`、`test`、`build` 全部通过。

## v0.2 恢复计划

1. 恢复个人介绍、照片区、关于我与页尾，移除固定单屏限制。
2. 把项目／运营 Tab 从网站顶栏移回作品内容区。
3. 让顶栏“项目作品／运营经历”分别选择对应 Tab，并定位到内容区。
4. 保留每个案例独立一页、左右箭头和键盘翻页。
5. 将案例首屏调整为结论先行、证据优先的叙事卡片，同时保持明亮实验室视觉。
6. 更新结构测试，执行格式、类型、测试、生产构建和浏览器视觉检查。

## v0.3 网站式演示交互计划

1. 将桌面首页改为固定视口的四栏目网站画布：首页、项目经历、运营经历、简历。
2. 项目与运营栏目内部保留一案一页和左右翻页，显示分类页码。
3. 使用网站式横向位移、淡入和轻微景深完成栏目与案例切换。
4. 把“查看完整案例”改为当前页面内的可滚动模态弹窗，关闭后保留浏览状态。
5. 手机端改为自然纵向排列，不强制固定视口或横向切换。
6. 更新结构与交互测试，完成桌面、手机、键盘和弹窗验证后提交部署。
