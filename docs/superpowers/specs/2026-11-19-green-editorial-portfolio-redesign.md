# 个人作品集绿色编辑手册风重设计

日期：2026-11-19  
状态：已确认，待实施

## 目标

在不改变既有信息架构和核心交互的前提下，将个人作品集从蓝紫色明亮实验室风改为米白、深绿与橙黄色构成的编辑手册风。作品集面向产品、AI 产品及运营类岗位，首要任务是让招聘方快速理解候选人的定位、项目判断、执行过程与成果证据。

## 已确认边界

- 保留四个一级栏目：主页、项目、运营、简历。
- 电脑端保持横屏单页体验，不通过上下滚动浏览一级页面。
- 项目和运营栏目中的案例继续支持左右翻页。
- 完整案例继续在当前页面内以详细弹窗呈现，不跳转独立页面。
- 手机端允许自然纵向滚动，保证文字完整可读。
- 本次只重做视觉系统、版式层级与必要的切换动效，不改变案例事实、成果数字和栏目数量。
- 用户未提供真实图片前，保留具有明确用途的素材位置，不生成虚假项目截图。

## 视觉方向

采用“编辑手册风”，不使用大面积蓝紫渐变、模糊光斑或无含义的装饰圆球。

### 色彩

- 暖米白 `#F4F0E6`：全站纸张底色。
- 森林绿 `#173F35`：主标题、主按钮和主要结构线。
- 苔藓绿 `#5E765E`：正文辅助信息与次级标签。
- 柑橘橙 `#E86F3D`：运营内容、关键动作与交互强调。
- 芥末黄 `#E7B84B`：页码、证据提示和局部高光。
- 深墨色 `#17231F`：正文，保证米白背景上的阅读对比度。

项目案例以绿色为主要识别色，运营案例以橙色为主要识别色，但两类内容共享同一套排版语言。

### 字体与字号

- 大标题使用中文宋体族，营造编辑出版物的个性，仅用于标题和关键结论。
- 正文、按钮和数据使用清晰的中文黑体族。
- 工具性标签使用紧凑字距和小字号，承担分类、角色、周期与页码信息。
- 桌面首页标题保持强识别度，但不得挤压个人介绍和主要操作；案例标题以一屏完整展示为硬约束。

### 结构语言

- 减少悬浮白卡、大圆角和平均分布的小卡片。
- 使用细线、块面、页码、栏目标签与非对称留白建立层级。
- 每个结构元素都表达真实信息：页码表示案例位置，色块区分项目与运营，细线组织叙事章节。

## 页面设计

### 顶部导航

- 固定展示“主页／项目／运营／简历”四个 Tab。
- 当前栏目使用深绿文字、短下划线或色块进行明确标识。
- 品牌信息保持克制，不抢占一级导航视觉中心。
- 切换栏目时保持横屏网站感，不模拟传统 PPT 工具栏。

### 主页

主页是整站观点表达，而不是普通个人简介模板。

- 左侧：职业定位、个人介绍和进入项目或运营栏目的主要操作。
- 右侧：保留个人照片区；在真实照片补充前使用明确标注的照片位置，不使用抽象渐变圆球。
- 主标题强调“把复杂问题做成可用方案”，并通过排版而非特效形成记忆点。
- 橙黄贴纸式标签可用于表达产品、AI、运营三个能力侧面，但数量保持克制。

### 项目栏目

- 一个项目占据一页，保留四个项目及左右翻页。
- 左侧形成案例主叙事：项目名称、一句话价值、角色周期、关键成果、三段核心判断。
- 右侧改为“项目证据板”，承载真实截图、流程图、数据证据或待补素材位。
- “查看完整案例”是唯一主要操作，视觉上清晰但不压过项目标题和结果。
- 当前案例序号和总数持续可见，左右按钮具备明确可点击状态。

### 运营栏目

- 一个运营经历占据一页，保留三类运营经历及左右翻页。
- 叙事结构突出目标、增长链路、具体动作和沉淀方法。
- 使用橙色作为局部强调，与项目栏目的绿色形成清晰区分。
- 右侧证据板优先承载内容截图、活动物料、增长链路或运营成果。

### 简历栏目

- 作为整站收尾，而不是简单的“简历待上传”占位页。
- 展示个人能力组合、经历摘要和简历获取区域。
- 在简历文件尚未确认公开前，不提供失效下载按钮；明确保留可替换位置。

### 完整案例弹窗

- 延续已确认的案例研究档案结构和七个案例的详细内容。
- 弹窗同步采用米白、深绿和橙黄色视觉语言。
- 桌面端使用左侧章节目录与右侧正文；手机端改为单列阅读。
- 标题约 34—42px，章节标题约 22—26px，正文约 15—16px，禁止再次出现标题过大、正文被挤出首屏的问题。
- 保留 Esc 关闭、遮罩关闭、焦点恢复和减少动态效果支持。

## 动效与交互

- 一级 Tab 切换：短距离横向移动与透明度变化，持续约 240—320ms。
- 案例翻页：内容沿翻页方向移动，页码同步更新。
- 弹窗：轻微上移与淡入，不使用缩放弹跳。
- 鼠标滚轮或触控板可用于项目、运营案例内部翻页时，必须设置触发阈值与节流，避免一次滚动跨越多页。
- 键盘左右方向键继续支持案例翻页。
- `prefers-reduced-motion` 下关闭非必要位移动画。

## 响应式规则

### 电脑端

- 视口宽度达到桌面断点后，四个一级栏目均控制在一屏内。
- 不允许正文、按钮、翻页控件或关闭按钮被底部裁切。
- 对矮屏使用紧凑字号、间距和证据板高度适配，而不是隐藏关键信息。

### 手机端

- 一级页面按栏目自然纵向排布，允许上下滚动。
- 顶部 Tab 可横向滚动或使用紧凑布局，但四项名称均需可见、可操作。
- 项目和运营仍保持一项一页的内容顺序；左右滑动与按钮均可切换。
- 弹窗占满可用视口并使用单列正文，不产生横向溢出。

## 内容与数据边界

- 沿用当前内容数据和已确认的成果口径，不新增未经材料支持的数字、经历或因果结论。
- 用户要求保留的测试结果与数字按现有内容原样呈现，不额外增加口径说明。
- 图片未到位时只展示用途明确的素材位，后续替换不改变版式结构。
- 不展示联系方式、内部系统敏感信息、用户隐私或访问凭据。

## 实现原则

- 以当前四 Tab 版提交 `245f369` 的信息架构为恢复基线，并吸收后续详细案例弹窗的数据与内容。
- 使用现有 Vite 与原生 TypeScript 技术栈，不引入 UI 框架或复杂动画依赖。
- 颜色、字体、间距和动效集中为 CSS 变量，项目与运营差异通过内容状态切换主题变量。
- 保持内容数据与视图渲染分离，避免把七个案例详情硬编码到页面模板。

## 验收标准

- 桌面端清晰显示主页、项目、运营、简历四个 Tab，且一级页面无纵向滚动。
- 四个项目和三类运营经历均可逐页查看，页码、按钮、键盘与鼠标滑动切换正常。
- 七个完整案例均可在详细弹窗中阅读，正文信息未退化或缺失。
- 米白、深绿与橙黄色视觉系统覆盖首页、案例页、简历页和弹窗，不残留蓝紫色主题组件。
- 1280×720、1440×900 和常见手机尺寸中，文字与操作控件完整可见。
- 键盘焦点清晰，减少动态效果设置有效，颜色对比满足可读性要求。
- Prettier 检查、TypeScript 类型检查、Vitest 测试与 Vite 生产构建全部通过。
- 发布前逐页截图复核主页、四个项目、三类运营、简历、至少一个长案例弹窗和手机布局。

## 不在本次范围

- 不补造用户尚未提供的个人照片、项目截图、视频或简历文件。
- 不增加后台、CMS、登录、访客统计或新的公开数据服务。
- 不改变已确认的案例事实和成果数字。
- 未经用户审阅本地效果前，不覆盖当前线上版本。
