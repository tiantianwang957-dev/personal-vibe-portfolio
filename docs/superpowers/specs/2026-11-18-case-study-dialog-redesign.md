# 作品集完整案例弹窗重设计

日期：2026-11-18  
状态：已确认，待实施

## 目标

把当前仅包含短摘要、字号过大的“完整案例”弹窗，重构为适合求职面试官阅读的案例研究档案。七个案例全部覆盖；详情仍在当前网站内以弹窗呈现，不跳转独立页面。

## 已确认原则

- 使用“案例研究档案式”而不是长文章或弹窗内 PPT。
- 七个案例统一设计语言，但项目与运营采用不同的叙事骨架。
- 只使用现有材料中已确认的事实；资料不足时保留明确用途的素材位，不虚构经历、动作或数字。
- 桌面端支持快速扫描和深入阅读；手机端自然纵向阅读。
- 继续保留现有明亮实验室视觉体系，避免重新引入复杂交互。

## 信息架构

### 通用顶部摘要

每个案例顶部展示：

1. 案例类型和编号；
2. 项目名称与一句话价值；
3. 角色、周期、项目状态；
4. 2—3 项核心证据；
5. “我负责什么”摘要。

### 产品项目章节

适用于海信、AIGC、汽车产品使用率 AI 平台和口袋公园：

1. 背景与挑战；
2. 目标用户与关键问题；
3. 我的判断；
4. 产品方案与核心链路；
5. 执行与协作；
6. 结果与证据；
7. 我的贡献；
8. 复盘与下一步。

### 运营案例章节

适用于新浪微博、摄影自媒体和家装用户增长与 AI 工具运营：

1. 业务目标；
2. 用户或增长问题；
3. 策略拆解；
4. 执行动作；
5. 结果与证据；
6. 我的贡献；
7. 方法沉淀与复盘。

章节允许依据真实材料合并，但不可为了统一数量而填充空话。

## 桌面布局

弹窗宽度接近视口但保留网站背景边缘，形成“打开项目档案”的空间感。

```text
┌─────────────────────────────────────────────────────┐
│ 案例标题 / 价值结论 / 角色周期 / 关闭               │
├──────────────┬──────────────────────────────────────┤
│ 章节目录      │ 核心指标与本人职责                   │
│ 背景与挑战    │                                      │
│ 用户与问题    │ 正文章节                             │
│ 产品方案      │ 流程、判断、卡片和素材位             │
│ 结果与复盘    │                                      │
└──────────────┴──────────────────────────────────────┘
```

- 左侧为粘性章节目录，显示当前案例的真实章节。
- 右侧为唯一主要滚动区，避免多层滚动。
- 标题约 34—42px，章节标题约 22—26px，正文 15—16px。
- 正文每行控制在适合阅读的宽度，避免一整行横跨大弹窗。
- 证据、流程和关键判断使用不同的信息组件，不把所有内容都做成同一种圆角卡片。

## 手机布局

- 弹窗占满可用宽度和高度。
- 左侧目录折叠为顶部横向章节导航。
- 所有章节单列自然向下排列。
- 正文字号不低于 15px，按钮触控区域不低于 44px。

## 内容与素材边界

- 海信：可展开业务痛点、五模块方案、角色责任边界、闭环链路、测试结果、成本测算边界和复盘。
- AIGC：展开创意输入、编辑、预览、实物交付和运营闭环；未核实数据不展示为成果。
- 使用率平台：展开三级指标、异常定位、任务触达、整改审核和复盘闭环；只使用虚构数据的脱敏重构。
- 口袋公园：展开调研方法、需求归纳、产品转化和社区治理建议；缺少的现场图、问卷图和原型使用素材位。
- 新浪微博：围绕活动参与、内容供给、创作者协同和复用资产展开；无公开数据时不生成假数字。
- 摄影自媒体：围绕定位、内容实验、公私域承接和商业化探索展开；时间和数据待有材料后补。
- 家装运营：围绕增长链路、服务角色、AI 工具推广和使用反馈展开；不公开内部页面、用户信息或受限数据。

## 组件与数据结构

- 扩展案例数据模型，使章节支持段落、要点、流程、证据卡、素材位和提示说明。
- 弹窗渲染器根据数据类型生成对应组件，不在模板中硬编码七个案例。
- 目录锚点来自章节数据，点击后只滚动弹窗内容区。
- 关闭弹窗后保留原栏目与案例页码。

## 交互与无障碍

- 保留原生 `dialog`、Esc 关闭、遮罩关闭和明确关闭按钮。
- 打开后焦点进入弹窗，关闭后回到原“查看完整案例”按钮。
- 目录按钮具备可见焦点状态。
- 尊重减少动态效果设置；章节滚动不增加装饰性动画。

## 验收标准

- 七个案例均拥有与类型匹配的完整章节，而非重复短摘要。
- 桌面普通屏和矮屏中标题、目录、正文、关闭按钮均可访问。
- 手机端单列阅读，无横向溢出。
- 无未经材料支持的新数字、新经历或新结论。
- Prettier、TypeScript、Vitest 和 Vite 生产构建全部通过。
- 浏览器逐一打开七个案例，至少核对首屏、目录滚动、末章节、关闭恢复位置和手机布局。

## 不在本次范围

- 不补用户尚未提供的真实截图、视频、联系方式或简历文件。
- 不增加独立案例路由、后台 CMS 或弹窗内翻页。
- 不改变首页、项目／运营一级栏目及左右翻页逻辑。

## 2026-11-18 补充交互：桌面滚轮切换

- 仅在桌面端的项目经历和运营经历主页面响应鼠标滚轮：向下切换下一案例，向上切换上一案例。
- 单次滚轮只切换一页，并设置 650ms 冷却，避免触控板或滚轮惯性连续跳页。
- 首页、简历、手机端和完整案例弹窗不触发案例切换；弹窗滚轮始终用于阅读长内容。
- 保留左右箭头和键盘方向键，滚轮是补充操作而不是唯一入口。
- 主页面摘要卡不得使用行数截断；矮屏通过紧凑间距和文案区内部滚动保证所有文字可到达。
